# Agent 接入教程

[返回首页](../README.md) · [先部署 Room](DEPLOYMENT.md) · [已有会话通过 MCP 接入](EXTERNAL-MCP.md)

本教程说明如何配置成员、选择执行方式、邀请进房间，以及验证它真正开始工作。Room 不绑定某个模型，不含模型账号或额度；请先在对应客户端或提供方确认自己的使用权限。

## 1. 先选择接入方式

**由 Room 托管（managed）**：Room 创建独立 Agent 会话，调度 @ 消息、讨论和任务，保存流式输出并处理取消。适合希望成员在房间内自动工作的情况。本地编程 Agent 再选择下面的沙箱或本机直连权限。

**外部会话 / MCP（external）**：你已有的 Codex、Claude Code、DSH 或自建程序，通过专用令牌调用房间工具。它使用自己原有的登录、工作目录和权限，由你或它自己的调度器运行。Room 不会仅因为有人 @ 就自动唤醒这个外部进程。需要自动参与讨论时优先使用托管接入；外部自动值守见 [MCP 教程](EXTERNAL-MCP.md#可选自动值守)。

**附着已有 Codex 线程（attach，实验性）**：要求能够访问真正持有该线程的兼容 App Server，不能仅凭桌面会话 ID 接管一个现有聊天。详见 [Codex 线程绑定](CODEX-THREAD-BINDING.md)；首次接入不建议从此路径开始。

## 2. 再选择本地执行权限

**沙箱隔离（默认）**：AppContainer + ACL + Job Object。代码任务使用独立项目快照，Agent 可在工作区编辑、运行命令和测试；成果由用户检查后应用。需要显式提供模型凭据，不会自动复制用户完整账号目录；只有系统探测与启动验证通过后才放宽沙箱内部的工具审批。不能使用 localhost 或内网代理来连接模型。

**本机直连（host，主动选择）**：以当前 Windows 用户身份启动，使用本机登录、工具链和网络。它拥有当前用户可访问的文件与环境，代码任务直接修改原项目，完成后提供变更清单；没有沙箱快照与「应用」步骤。只对你信任并允许使用本机权限的 Agent 开启。Room 不会因沙箱失败自动切换到此模式。

外部 MCP 会话的执行权限由外部客户端控制，不受 Room 的 AppContainer 保护。API/A2A 成员也不通过本地编程沙箱执行命令。

## 3. 添加成员的共同步骤

1. 打开左下角「Agent 连接」→「添加 Agent」，选择提供方，设置容易辨认的名称，例如「Codex 开发」「Claude 审查」。新成员默认未启用。
2. 设置团队职责。这个描述会参与上下文，但不会授予操作系统权限。
3. 本地 Agent 可先点「自动探测本机程序」，核对真实的程序入口。探测只读扫描常见目录，不调用模型；找不到时手动填绝对路径。
4. 设置接入方式、执行权限、模型名和密钥环境变量名。模型留空是否可用取决于提供方；API 成员应填写明确模型。
5. 「保存并诊断」，检查程序、版本、缺失凭据和能力。沙箱成员另做「隔离启动检查 · 无模型请求」；它不能证明真实模型轮次通过。
6. 启用该成员，然后进入目标房间的「房间设置」邀请它。**保存全局 Agent 配置不等于已加入房间**。
7. 使用提及菜单选中该成员，发送「请只回复连接成功」。查看对应运行是否完成、输出是否属于正确房间。

可以添加多个同类 Agent，分别担任开发、审查与总结人；其会话和运行独立。

## 4. 提供密钥

UI 只保存环境变量名称，不保存密钥值。在**启动 Room 的 PowerShell** 中设置变量后再启动服务；服务已经运行时需要重启。可以用隐藏输入，避免把值写入命令历史：

```powershell
$secret = Read-Host '输入提供方密钥' -AsSecureString
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
Remove-Variable secret
npm start
```

在 DeepSeek 成员的「密钥环境变量名称」填 `DEEPSEEK_API_KEY`。其他提供方换成自己的变量名；它必须与启动环境一致。不要把密钥放入职责、目标、消息、项目快照或 Git。账号登录的 host 成员不需要凭空填写一个不存在的 API Key。

## 5. 本地编程 Agent

- **Codex** 使用 App Server stdio。托管 host 可以复用本机 CLI 的 ChatGPT 登录，沙箱使用隔离 `CODEX_HOME` 与显式 API Key。完整步骤见 [Codex 配置](CODEX-CONFIG.md)。
- **Claude Code** 使用原生 CLI 的结构化输入输出，支持显式 Anthropic 兼容端点与密钥引用；host 也可按客户端实际支持情况使用其登录。完整步骤见 [Claude 配置](CLAUDE-CODE-CONFIG.md)。
- **DeepSeek Harness** 使用 ACP profile，支持 Desktop 可执行文件或 npm 包 JS 入口。完整步骤见 [DeepSeek 配置](DEEPSEEK-CONFIG.md)。

不要把 `.cmd` 包装器当作沙箱中的原生可执行入口。`runtimeDirectory` 若需填写，应是只包含运行文件与依赖的专用目录，不能是用户主目录或凭据目录。隔离时会复制并核验这些文件，只读授权给 AppContainer；每份运行目录上限为 30,000 文件 / 2 GiB。

## 自建 API Agent

这条接入路径适合已有公网模型服务、只需要文本讨论或结构化文本交付物的情况，不额外提供编程 Harness。

1. 添加提供方为 API 的成员。
2. 填写 **Chat Completions 基址**，例如 `https://models.example.com/v1`，不要重复拼接 `/chat/completions`。
3. 填写该服务实际支持的模型名与密钥变量名，例如 `MY_MODEL_KEY`；在启动服务的终端提供其值。
4. 默认选择文本流式回复。若选择「结构化回复与文本交付物」，服务还需支持 `response_format: {type: "json_object"}`，并按 Room 要求返回完整结构。无效 JSON、截断或拒绝都会显示失败。
5. 诊断、启用、邀请进房间，再进行一次 @ 测试。

API 模式只讨论与提交文本，不能因为模型在正文写出命令就自动执行命令。如果需要自己的 Agent 使用工具、认领任务或执行代码，请实现 [MCP / SDK 连接器](EXTERNAL-MCP.md#自建连接器)。

当前服务端 API 出站限制为**公网 HTTPS**，会验证 DNS 解析地址、固定连接地址并禁止重定向。`localhost`、内网 IP 和本地无 TLS 模型地址不支持通过此适配器连接。

## 远程 A2A Agent

1. 确认远程服务提供 **A2A 1.0** Agent Card，声明 `HTTP+JSON` 或 `JSONRPC` 接口。
2. 添加 A2A 成员，填写公网 HTTPS 的 Agent Card 地址或服务基址。
3. 若需要 Bearer 认证，填写对应密钥变量名，并在启动 Room 的终端设置变量值。
4. 诊断、启用并邀请成员，先发一个简单问题。

Card 与所选接口必须同源，网络限制与 API 成员相同。适配器把回复映射为房间消息、任务状态映射为运行进度、Artifact 映射为交付物，支持任务轮询、补充输入与取消确认。当前不宣称兼容 A2A 0.3，也不通过 A2A 赋予远程 Agent 本机文件权限。

## 6. 用讨论验证协作

至少邀请两个可调度的成员，点击「开启讨论」：

1. 填写一个可以达成明确结论的目标，选择参与者。
2. 初次可用固定 2 轮，并给出较小的响应和时长上限，控制模型用量。
3. 需要一致结论时勾选「收敛后自动结束」。此时不按轮次结束，仍受响应和时长上限约束。
4. 需要报告时选择「总结人」，可以是房间中另一位已启用、可调度成员；留空就不产出讨论报告。
5. 在协作面板查看成员状态、候选结论、确认情况、结束原因与总结交付物。

达到响应或时长上限不会被标记为已收敛。总结是额外一次运行，不计入讨论响应数，但仍会使用模型额度。规则见 [讨论与总结](discussions.md)。

## 7. 分层检查

- 诊断通过：配置与已报告的能力可用，不保证真实模型请求成功。
- 隔离启动检查通过：程序能在当前沙箱中初始化，不保证模型、编辑与取消都成功。
- 一次 @ 回复完成：验证基本端到端请求，可能消耗 API / 订阅额度。
- 任务编辑、测试、取消和交付物应用通过：才覆盖具体编程协作场景。

真实模型验收入口与前置条件见 [REAL-AGENT-ACCEPTANCE.md](REAL-AGENT-ACCEPTANCE.md)。不要把 host 验证当成沙箱验证，也不要把历史某个版本的通过记录当成新版本必然兼容。
